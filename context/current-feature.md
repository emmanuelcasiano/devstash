- **2026-09-24** — AI Description Generator (Completed): built per an inline request (no `context/features/` spec) to add a "Generate description" button beside the item Description field, following the pattern the AI Auto-Tagging feature established. New pure, Prisma/auth/Gemini-free `src/lib/ai/describe.ts` mirrors `auto-tags.ts`'s shape: `generateDescriptionInputSchema` (every field — `title`/`content`/`url`/`fileName`/`language` — is optional/nullish-normalized, with a `.refine()` requiring at least one of title/content/url/fileName so there's something to summarize), `descriptionSuggestionSchema` (`{ description: string }`, 1-300 chars, passed to Gemini's `responseJsonSchema` via `.toJSONSchema()`), `buildDescribePrompt` (assembles whichever fields are populated into labeled lines — `Title:`/`Language:`/`URL:`/`File name:`/`Content:`), `truncateDescribeContent` (2000-char cap, same limit as auto-tags), and `parseDescriptionSuggestion` (JSON-parses and trims Gemini's response, `null` on malformed/blank output). Reuses the existing `AI_MODEL` (`gemini-3.5-flash-lite`) from `auto-tags.ts` rather than duplicating the constant. **Action** — `src/actions/ai.ts` gained `generateDescription(input)` following the same shape as `generateAutoTags`: `requireUserId` → Zod validate → Pro gate (`hasProAccess(getCurrentUserIsPro())`) → `isGeminiConfigured()` check → rate limit → try/catch → `ActionResult<T>`; `src/lib/rate-limit.ts` gained a separate 20/hour `aiDescribe` limiter (not shared with `aiAutoTag`) keyed on `session.user.id`. **UI** — new `src/components/items/DescribeButton.tsx` (client): a ghost icon-only button (`WandSparkles`, ghost `icon-sm`) next to the Description field's label, hidden entirely for Free users via `usePlan().hasPro` (UI-only — the action enforces Pro server-side), disabled when there's no usable title/content/url/fileName; on click it calls the action and overwrites the Description field via `onGenerate` — no accept/reject step, unlike `TagSuggestions`, since a single description has no per-item chips to accept individually. `src/components/ui/field.tsx` gained an optional `action?: React.ReactNode` prop rendered next to the label (small, non-breaking addition — every existing `<Field>` call site is unaffected) so the button sits inline with "Description" instead of needing a new layout. New `buildDescribeInput(form, fileName)` helper in `src/components/items/item-form.ts` assembles the button's payload from the shared `ItemFormValues` plus a separately-passed file name (file/image items have no content/url, so the file name is the only fallback signal) — deliberately excludes the current Description value itself, since generating/replacing it is the whole point. Wired into `NewItemDialog.tsx` (passing `upload?.fileName`) and `ItemEditFields.tsx`/`ItemDrawer.tsx` (passing `item.fileName`, plus a new `onDescriptionChange` callback mirroring the existing `onContentChange`/`onLanguageChange` pattern, since `DescribeButton` hands back a plain string rather than a change event). **Tests** — new `src/lib/ai/describe.test.ts` (13 cases: schema acceptance for title+content, file+fileName-only, and URL-only payloads, rejection when nothing is populated, content truncation, prompt assembly with various fields populated/blank, and response parsing incl. malformed/blank/schema-mismatch). `npm test` 15 files / 187 tests → 16 files / 200 tests. The action itself got no unit tests, consistent with `generateAutoTags` (Gemini/`auth()` calls, no mocking harness); `DescribeButton` and the dialog/drawer wiring are out of scope per the Testing standard (React components). No DB migration, no new packages, no new env vars; the build route list is unchanged (server actions add no routes). Verified with Playwright against the running dev server as the Pro `demo@devstash.io` user, with real Gemini calls (not mocked): in the New Item dialog, typing only a title ("useDebounce Hook") into a new snippet and clicking Generate produced "A custom React hook that delays updating a value until a specified time has elapsed since the last change." in the Description field; in the item drawer's edit mode for the existing "Docker Documentation" link item (title + URL, no content), Generate replaced "Official Docker documentation." with "The official documentation website for Docker, providing guides, references, and resources for containerization and application deployment." — both edits were cancelled afterward rather than saved, leaving seed data untouched. - **2026-09-25** — AI Prompt Optimizer (Completed): built per an inline request (no `context/features/` spec) to add a Pro-gated "Optimize" button to the prompt markdown editor's header, mirroring the "Explain" button in the code editor's header (snippet/command) — the button refines the current prompt via Gemini and shows the result as a suggestion the user explicitly accepts or discards, never applied automatically. New pure, Prisma/auth/Gemini-free `src/lib/ai/optimize-prompt.ts` mirrors `explain.ts`'s shape: `optimizePromptInputSchema` (`title` optional/trimmed, `content` required non-blank), `optimizedPromptSuggestionSchema` (`{ prompt: string }`, 1-6000 chars, via Gemini's `responseJsonSchema`), `buildOptimizePromptPrompt`, `truncateOptimizePromptContent` (4000-char cap — higher than the other AI features' 2000, since a prompt being optimized can reasonably run longer than a snippet/description source), and `parseOptimizedPrompt`. `OPTIMIZE_PROMPT_MAX_OUTPUT_TOKENS = 800`. **Action** — `optimizePrompt(input)` in `src/actions/ai.ts` follows the established `requireUserId` → Zod validate → Pro gate → `isGeminiConfigured()` → rate limit → try/catch → `ActionResult<T>` shape; `src/lib/rate-limit.ts` gained a separate 20/hour `aiOptimizePrompt` limiter keyed on `session.user.id`. **UI** — `src/components/items/MarkdownEditor.tsx` gained `title`/`showOptimize` props and a third `"suggestion"` tab state (alongside the existing Write/Preview tabs), only rendered once a suggestion exists or is loading; an `OptimizeButton` (mirroring `CodeEditor.tsx`'s `ExplainButton` — visibly disabled with a Crown icon + "AI features require Pro subscription" tooltip for Free users, rather than `DescribeButton`'s fully-hidden pattern) sits in the header next to Copy, shown only when `showOptimize && !readOnly`. Clicking Optimize switches to the Suggestion tab, shows a loading skeleton, then the rendered Markdown suggestion with "Discard" (clears it, returns to Write) and "Use this version" (calls `onValueChange` with the suggestion, then returns to Write) buttons — unlike Explain (read-only, no accept step) and the Description generator (overwrites immediately with no accept step), this is the first AI feature in the repo with an explicit accept/reject UI. `ItemContentField.tsx` threads `title`/`showOptimize` through to `MarkdownEditor`, gating `showOptimize` to `typeName === "prompt"` only (not notes, even though both share the markdown editor) — mirrors how `showExplain` is scoped to snippet/command via `EXPLAIN_ITEM_TYPES`. Wired into both `NewItemDialog.tsx` (create form, passing `form.title`) and `ItemEditFields.tsx` (drawer edit mode, passing `form.title`) — unlike Explain, which is read-view only, Optimize only makes sense while the content is still editable, so `ItemDetailView.tsx` (read view) was left untouched. **Tests** — new `src/lib/ai/optimize-prompt.test.ts` (12 cases: schema acceptance/rejection, content truncation, prompt assembly with/without a title, and response parsing incl. malformed/blank/schema-mismatch). `npm test` 17 files / 212 tests → 18 files / 223 tests. The action itself got no unit tests, consistent with `generateAutoTags`/`generateDescription`/`explainCode` (Gemini/`auth()` calls, no mocking harness); `MarkdownEditor`'s new UI is out of scope per the Testing standard.
